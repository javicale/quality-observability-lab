# Observability and evidence contract

## Identifiers

- Execution UUID: one `npm run demo` invocation; directory name.
- `test_run_id`: execution UUID plus scenario. Sent as `x-test-run-id`, stored as `test.run_id` on spans/logs, returned as `test_run_id` in JSON.
- Trace ID: 32 lowercase hex characters generated in the test; propagated using W3C `traceparent`.
- Parent span ID: remote test context. It is a propagation anchor, not an exported browser span.
- Server span ID: generated by OTel. Logs carry it and the inventory span references it.

The gate verifies response → server span → child span → log, including exact trace/run IDs and parent relationships. The failing child must have an exception event; the server must have error status and HTTP 500. A valid normal scenario requires HTTP 200 and unset span error status.

## Metrics

`lab.http.requests` counts completed checkout operations. `lab.http.duration` measures synthetic operation duration in milliseconds before telemetry flush and network response. It is not browser end-to-end latency. Both use `http.route`, `http.response.status_code`, and `lab.scenario` attributes.

SDK exports are cumulative snapshots. **Do not sum repeated snapshots**: use the latest point for each attribute set. Flushes produce multiple snapshots in a run. Run IDs are deliberately excluded from metric labels; this baseline does not claim trace exemplars. Metrics are joined to evidence using the isolated run directory plus scenario/status.

## Evidence format v1

Each scenario JSON records `schema_version`, `scenario`, `test_run_id`, `trace_id`, `parent_span_id`, expected/actual HTTP status, `outcome`, `injected_failure`, response body and screenshot path. JSONL files contain actual records emitted through OTel SDK exporter interfaces. This is a local teaching format, not an OTLP serialization contract.

`quality-gate.json` explicitly distinguishes healthy checkout PASS, injected checkout FAIL and failure-detection PASS. Missing/malformed files fail closed. Unit tests mutate correlation, parent relationships, child spans, logs, metrics, exceptions and status codes to demonstrate rejection.

## Evidence limitations

Files are not signed or tamper-proof. Metric values are experiment observations, not an SLO. Manual invocations share `artifacts/manual` until restarted and are not quality-gate inputs. IDs are untrusted input validated for shape, not authentication. No request bodies, credentials, customer payloads or arbitrary headers are logged.

References: [OpenTelemetry JavaScript instrumentation](https://opentelemetry.io/docs/languages/js/instrumentation/) and [Playwright expected failures](https://playwright.dev/docs/test-annotations).
